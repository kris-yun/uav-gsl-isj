# M1/M2 真实有效：最小改进路线（设计提案，尚未实施）

基于 HEAD 46b33b6、R4 原始证据和当前代码。目标不变：M1 源推断更准确，M2 输运预测带来额外闭环收益。不能保证两项都会成功；不降低 gate、不删除负结果、不把静态 PASS 当任务收益。

## 本轮新核实的实施前提

1. 在线风场已有接口：`PMFSLib::EstimateWind` 从 `/WindEstimation` 写入 `estimatedWindVectors`。应使用截至当前时刻的 GMRF 估计快照；服务失败时现有实现仅警告，新接口必须显式记录陈旧状态。不得把离线 GADEN 全场/未来风序列冒充在线测量。
2. 数值 M2 需要数值契约修复：`advance` 固定 dt=1 s、dx=0.3 m、D=0.01，显式迎风加扩散后直接截零。合成 9×9 内部脉冲、恒风 u=v=0.15 m/s、另一内部格点单位源，一步期望总量 2，实际 2.4444444444。内部中心系数为 1-dt[(|u|+|v|)/dx+4D/dx²]=-0.4444，截零造成增加。脚本 `tools/probe_ctpi_m2_step_contract.py` 可复现；不涉及 bank，不说明该现象在原 House 的发生比例。
3. R4 配置 `fopdt_tau1p2_dead0p4_noise0`；M1 用 measured ppm 的累计格点峰值直接对照 plume 形状，没有在似然预测侧执行同一传感器响应。时间戳正确关联到当前位置，并不等于消除了传感器历史响应。

## 路线：先使两个模块比较同一种观测，再检验收益

### P0：修复并版本化 M2 的数值与输入契约

- 保留旧 solver/旧 field PASS。新版本采用有明确通量与边界语义的离散推进、由稳定性条件决定内部子步，外部采样时钟不变。非负应由数值方案保证，不能依靠大幅截零掩盖不稳定。
- 单测：零场、恒风平移、纯扩散、含源质量收支、墙面通量、dt/dt2 收敛、非法/陈旧风输入。不凭数学修复继承旧 field PASS，新实现需要重新验证。
- 使用当前在线 GMRF 风快照、几何与候选源；记录输入时间与哈希。未来风没有观测值时，只能使用预先明确的因果预测规则，并将预测误差纳入验证。
- 最小干预端到端接口：每个候选源输出按时刻对齐的预测浓度序列，而非离线全程峰值表。先做同输入参考实现/运行时输出一致性，再接真实在线输入。

### P1：M1 改观测似然，不先用降温或追 MAP 调参救结果

- 保存时间、位置、原始 measured ppm 和传感器状态；废止“所有历史峰值统一由当前风解释”的新版本实现。
- plume 对照与数值 M2 输出必须经过相同的既有传感器响应模型，再与 measured ppm 比较。响应实现优先复用模拟器同源代码并做 parity，不另造一个近似公式冒充等价。
- 在不重叠测量块上更新；若使用递推后验，只引入新块，不重复乘入全部历史证据。相关性/误差尺度须由开发数据或既有传感器契约决定；不能把高频相关采样当成独立证据。
- 明确处理未知源强这一干扰因素，避免最大值归一化直接抹去幅值与零观测的含义。选定可复现的源强处理与误差模型后冻结；不能在看完 H02/H03 真值后选温度、窗口、尺度。
- 输出完整后验、实际 ESS、预测残差、每块证据贡献。真源 rank/邻域质量只由独立的事后 evaluator 计算。
- 这是一项待检验的模型改进，不是已经证明能消除错误高置信。若同轨迹的源推断精度仍无改善，不进入昂贵闭环。

### P2：统一控制器，隔离模块贡献

- 首轮对照使用同一个冻结、truth-blind、能消费源后验的导航规则；分开关闭原来 M1 内捆绑的直接 MAP 覆盖。不能只让新 arm 使用改良 controller。
- 导航候选、速度、停止规则、M3 禁用等保持相同。记录 native/selected goal、选择原因与后验，不能靠最终轨迹猜分支。
- 最小顺序对照：A0 原估计器；A1 新 M1 + 明确冻结的 plume 对照；A2 同一个新 M1 + 数值 M2。三个 arm 共享控制契约；A1-A0 检验该上下文的 M1 收益，A2-A1 检验 M2 在 M1 上的增量，同时报告 A2-A0 总收益。
- 该三臂结果是有条件的模块增量，不支持“任意消费者都有效”。若需双向独立主效应/交互项，还需先解决接口兼容再设计四臂，不伪称已有完整 factorial。

## 快速验证顺序与停止条件

1. 数值/时钟/传感器/接口单测。失败则修定义级错误，不跑闭环。
2. 用已花费数据做固定轨迹回放和影子预测。按时间先预测、后评分，不泄漏未来；用相同轨迹比较 M1 真源邻域质量/误差，以及 M2 预测误差。回放只能筛除明显无效方案，不能证明新策略闭环收益。
3. 把通过的唯一版本冻结，再跑预先选定的三屋闭环 screen；批中不读结果、不调整。沿用旧严格收益门槛作为新版本 screen 的基准，并明确新旧 controller/算法身份。
4. 同时报告最终误差和真实进入定位阈值的比例，避免重复 H03 “AUC 更好但末端崩塌”的误读。

seed12 已经用于归因，继续使用只能标为开发/确认性不足的 screen。不能将已经看过的数据重新叫 held-out。真正独立确认需要先审计现有获准 seed 的使用历史；如果都已花费，须另行取得新数据授权。本轮不新增 seed、不启动实验，也不改写旧冻结公式与结论。

## 为什么这是当前优先路线

两项直接矛盾都在建模与接口层：数值推进可能靠截零掩盖不稳定；预测浓度与滞后传感器读数并非同一可观测量。先处理这两项，比调 `-100`、选择风向窗口或为每个 House 设置信任阈值，更能检验可迁移收益是否真实存在。失败归因仍需实验证明，修复并不预先保证有效。
