## 2. 关键风场修改：保留什么，不能怎么用

### W1：按消费者修复方向与观测位置

当前 VGR 发送 map 系下风向；当前 GMRF 订阅回调按上风向再加 π，
同时 map→map TF 将观测位置取成原点。隔离二进制探针中，输入 (+1,0)，
旧消息路径输出 u 约 -1，显式位置/下风向服务输出 u 约 +1。

新增 `closed_loop/ctpi/ctpi_v2_wind_observation.py`，用同时间戳 UAV 位置编码请求。
**没有全局翻转模拟器风角**：原 Algorithm 消费者本来按下风向处理。
没有覆盖安装库；编码器不是已部署的常驻节点。空服务响应不证明核心实际插入成功。
详见 [实际二进制结果](CTPI_V2_GMRF_WIND_INTERFACE_RESULT_20260905.md)。

### W2：同步风生产器及导航高度地图对齐

新增 `CTPIGmrfWindV2.hpp` 与可回放 C++ 工具，显式检查插入和场的有限性，
记录截止时间；先用过去场预测，再插入当下风值，不能预测自己。
R1 默认地图/参数首条拒收；R2 按既有启动配置在 step102 拒收。

查实 GMRF 图片地图与导航 3D 飞行高度切片不一致：1200 个位置在导航切片均自由，
269 个在旧图片落于占据格。R3 只换成已哈希绑定的导航切片，1200 更新全部完成。
这解释当前插入失败，不证明历史 R4 全部失败都由地图引起。
详见 [地图与风预测](CTPI_V2_SHARED_GEOMETRY_WIND_RESULT_20260905.md)。

### W3：检查线性求解、原松弛关系与非线性停止条件

新增 `CTPIGmrfCheckedWindV2.hpp`：求解前清为 NaN 防止沿用旧解，
检查求解状态/有限性，独立重建右端项验证后向残差，检查原 0.5 松弛关系，
至少两步、原相对阈值 0.01、最多 100 步。失败明确终止，不假装完成。

| 风参考路径 | 结果 | 下一步局部风向量 RMSE (m/s) |
|---|---|---:|
| R3：导航地图，一步更新，累计观测 | 1200 更新 / 1199 预测 | 0.371126 |
| checked_cumulative：增加数值检查与迭代 | 1200 更新 / 1199 预测 | 0.369889 |
| 保持上一条局部风读数 | 同一 1199 预测时刻 | 0.256966 |
| checked_latest_cell：每格只留最后读数 | step111 / 22.2 s 未收敛 | 不将失败前缀报为完整成绩 |

收敛修正没有消除预测差距，因此“多迭代就会有效”没有得到支持。
每格最新只是时间证据消融，不是已校准动态滤波器；其他未访问格依旧可能陈旧。
详见 [两臂数值/时间消融](CTPI_V2_CHECKED_WIND_RESULT_20260905.md)。

### W4：失败迭代的无算法改动追踪

新增编译期追踪，取得逐次固定点变化。失败点和原预测/审计 CSV 哈希保持完全一致。
第 100 次相邻变化 0.012170、隔一步变化 0.010803，线性残差约 2.99e-17。
线性解精确不代表固定点收敛；证据不支持简单宣称已锁定二周期，也未证明最终发散。
详见 [最新追踪报告](CTPI_V2_WIND_FAILURE_TRACE_RESULT_20260906.md)。

**所有风修改当前均是隔离构件/诊断路径，未接替正式 ROS 算法。**
同一个修复输入层必须供未来全部比较臂使用，不能只给新臂纠正方向/地图。
局部风预测不是全场真值，GMRF 条件均值/边际方差不是跨时空联合输运后验。
