# CTPI G2-M1 v2 方案：瞬时场 + 时间对齐

日期：2026-09-04
前置：`CTPI_G2_M1_OFFLINE_FALSIFICATION_20260904.md`（v1 峰值场形状似然，offline rank=1 但真实闭环 3.74m）
性质：G2-M1 v1 真实闭环验证后的第一次 failure-driven 迭代。

---

## 1. v1 真实闭环结果与三个关键发现

### 1.1 v1 结果
- G2-M1 峰值场形状似然 C++ 实现完成，F00 smoke 跑通（无 crash）。
- 定位误差 3.74m（estimate -2.6,-5.93 vs 真源 -0.40,-2.90），比旧二值 7.35m 好一半，但未到源。

### 1.2 三个关键发现
1. **峰值场抹掉时变风向**：bank 峰值 = max over 1500 time（覆盖所有风向，源位置最高）；真实观测是"采样时刻风向"的羽流。
2. **时间轴错位 bug**：gas `header.stamp` = vgr simTime（step*0.2），但 gas 的 PPM 是 GADEN iteration（`(7919*(seed+1)%1998 + step) % 1998`，seed=0 offset=1925）；`recordCPIRRawSample` 用 simTime 算 timeIndex 查 bank（bank 是 step 1..1500）。两者错位。
3. **观测覆盖限制**：机器人从未采到 y<-2.0（源在 y=-2.90），只有下游羽流。

### 1.3 决定性验证（_tmp_m1_downstream.py，只有下游观测 y>-1.8）
| 方法 | rank |
|---|---|
| 峰值场（稳态） | 197/210（彻底失败） |
| 多时刻瞬时场 | 36/210（好很多，仍不理想） |

## 2. v2 设计

### 2.1 核心：瞬时场（时间序列）替代峰值场
- 峰值场抹掉风向，下游观测下彻底失败（rank 197）。
- 瞬时场保留风向，下游观测下 rank 36（好 5 倍+）。
- **v2 似然核**：对比观测与 bank 在**相同时刻**的浓度（时间对齐），而非 max over time。

### 2.2 时间对齐修复（发现 2）
- bank 的 time 0-1499 = 生成器 step 1..1500（t_sim_s=0.2*step）。
- vgr replay iteration = (offset + step) % 1998，offset=1925（seed=0）。
- 修复方向（待定，二选一）：
  - (a) 让 vgr replay 的 max_iteration=1500（bank 范围），使 iteration ∈ [0,1499] 覆盖 bank；
  - (b) 让 recordCPIRRawSample 用 iteration（从 simTime 逆映射，需 seed）。
- 需先确认 main_v8 生成器内部 step→wind 的映射，保证 vgr replay 与 bank 生成用同一风场时间序列。

### 2.3 transport 边缘化
- 8 member = 8 个 transport_seed（prediction_transport_keys）。瞬时场下，对每个 carrier 用 8 member 在相同时刻的浓度边缘化（平均或贝叶斯求和）。

### 2.4 观测覆盖（发现 3，M3 职责）
- 源定位精度上限由观测覆盖决定：只有下游观测时源定位病态（多个上游源产生相同下游羽流）。
- M1 的目标是"观测充分时 rank=1"（已 offline 验证）；"让机器人走到源附近"是 M3 探索的职责，不在 M1 阶段解决。

---

## 3. v2 实现路径

1. **offline 先验证**：用真实观测特性（短时羽流 + 时变风向 + 下游观测），验证"瞬时场 + 时间对齐"似然核的 rank（对比峰值场 197 → 瞬时场 36，目标进一步逼近 1）。
2. **时间对齐**：确认 main_v8 step→wind 映射，统一 vgr replay 与 bank 的时间轴。
3. **C++ 实现**：recordCPIRRawSample 用正确 iteration；applyCPIRPosterior 用瞬时场似然（时间对齐 + 8 member 边缘化）。
4. **smoke 验证**：真实闭环 F00，对比 v1（3.74m）与 v2。

---

## 4. 关键教训（offline falsification 方法论）
- v1 的 offline"峰值场 rank=1"是**自我一致**（观测=预测=峰值场），没暴露"真实观测是短时羽流 + 时变风向"。
- **offline 验证必须用真实观测特性**（机器人轨迹 + 采样时刻 + 传感器），不能用 bank 的理想峰值场。
- 下游观测验证（_tmp_m1_downstream.py）才是暴露"峰值场抹风向"的正确 falsification。
