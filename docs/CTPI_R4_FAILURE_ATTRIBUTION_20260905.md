# R4 离线失败归因：先纠正模块身份，再讨论适用条件

日期：2026-09-05。分析对象：HEAD `46b33b6` 保存的 R4 九组 H01/H02/H03、seed12、A0/F00/F01 证据。运行算法提交为 `a897ab31ad53ecb2ef5a1c53d2aa85aa51735c21`，该提交到 HEAD 的 `ros2_package` 无差异。

本报告是事后、描述性的归因审计，不是新的资格 gate，不把假设写成因果结论。没有重跑实验、调参、增添 seed、修改算法或读取 bank 预测载荷。原 NO_GO 和原始证据保留。

## 1. 对建议的判断，以及必须更正的旧解释

“先分析而非继续找赢的 seed”“NO_GO 不等于思想永久失败”是对的。但以下判断超出了当前证据：

- 运行完整、terminal guard PASS，只能排除该 guard 覆盖的运行故障，不能排除模块语义接错。
- 预注册条件不是“所有 House 都提升”：要求 AUC 至少赢 2/3 House、平均 AUC 降低、最终误差不能三屋全输。R4 是一个 seed 的筛选，不足以确定环境适用边界。
- “闭环有变化”不等于“正确因果推断机制已经证明”；F00 同时改了似然与导航，不能分离两者贡献。
- 最关键：此前场预测 PASS 的数值 M2，与 R4 F01 的所谓 M2 不是同一个实现。因此不能由 R4 推断“已验证的数值 M2，其预测能力没有转化为控制收益”。这是旧报告解释必须收窄之处。

### 排除“只是时间戳不同”的解释

旧 causal checker 的估计签名包含时间戳，理论上仅时间抖动就能通过差异检查。本次另行比较目标坐标，以及删除连续重复和时间戳后的 MAP 坐标序列：六组对比两者都真实不同。

六组首次目标分歧都在第 4 个目标，且发生于首次 CPIR 后验更新之后；前三个目标坐标相同。这支持后验更新之后产生导航差异的时序链，但不是推断正确性或中介效应的证明。首次更新前的 AUC 差异绝对值至多 3.700 m·s，主差异并非启动期贡献。各屋 0–60 s 的 AUC 在三个 arm 完全相同。

## 3. 三个 House 的具体失败过程

### H01：M1 相对基线较好，最近风向版本多数时段更差

F00 四次更新的 MAP 误差依次为 6.308、5.803、6.104、6.202 m；F01 为 7.592、6.756、8.535、5.917 m。F01 最终略好，但此前长时间更差，因此 F01-F00 AUC 为 +232.557 m·s。

F01 首次更新熵 2.198 nats，低于 F00 的 3.637，但误差更大（7.592 vs 6.308 m）。这是“更集中但更错”的直接样例，不支持“只要降低熵就会更接近真源”。首次新目标分别等于这两个错误 MAP。14/13 个发送目标中，F00/F01 分别有 3/5 个重复坐标；基线 14 个目标无重复。重复是追逐固定高后验位置的可观测症状，不单独证明效率损失由它造成。

### H02：M1 不是一直无效，而是第二次更新发生定位退化

F00 在 66.762 s 首次更新时误差 2.243 m；117.362 s 第二次更新跳到 7.102 m，随后为 5.698、5.698 m。同期熵从 4.701 略降至 4.676，因而不能把退化解释成单纯“后验变得更不确定”。

F00 相对 A0 在 120–180 s 的 AUC 多出 234.541 m·s，占全程恶化 377.158 m·s 的约 62%。主要问题在更新后的后验位置，而不是没有产生后验。

F01 相对 F00 全程仅恶化 4.253 m·s，不能凭这一个接近的数值宣布稳定无益。它的第二次更新同样退化到 6.774 m，最终 6.896 m；现有记录不能区分历史峰值、输运近似和改变后的采样路径各自的责任。

### H03：F01 的累计改善掩盖了错误高置信与末段崩塌

| F01 更新时刻（s） | 最大格点概率 | 熵（nats） | MAP 误差（m） |
| ---: | ---: | ---: | ---: |
| 70.500 | 0.9560 | 0.1887 | 4.129 |
| 122.800 | 0.1172 | 3.1580 | 4.588 |
| 175.300 | 0.4208 | 2.1188 | 3.961 |
| 227.900 | 0.0119 | 5.1862 | 11.785 |

第一次更新把 95.6% 质量放到错误 MAP `(2.9,-0.513)`，约 0.41 s 后发出的目标正是该位置。代码信任门只检测集中程度：`maxP>2/N` 且 `ESS<N/2`。这里 N=626，仅由 maxP 就可推出 ESS≤1/(0.956²)≈1.095，故集中度门会通过；它不检查位置正确性。这里是“错误高置信可通过控制信任门”的具体证据，但日志没有记录 native goal/最终分支，不能定量分离 controller 的责任比例。

此前大部分时间 F01 误差约 4 m，比 F00 的 6–10 m 低；最后一次更新才跳到 11.785 m。因此累计 AUC 较好与最终误差更差并不矛盾。这不是定位成功，也不支持可靠收敛。

## 4. 可疑机制、已知缺口与不可下的结论

**代码可证的错配：** F01 用最新风向解释所有历史访问格点的累计浓度峰值。不同峰值可能发生在不同输运时刻，其时间归属已被最大值汇总丢失。F00 对历史风向取最大也不是逐观测时刻对齐的预测；两者均非已通过 gate 的数值场预测器。

**有证据支持的风险：** 后验集中并不保证位置正确；集中度门允许错误高置信进入 source-seeking，且目标重复与错误 MAP 追逐真实可见。

**尚未识别的因果根因：** 不能据此断言“因为 H02/H03 风更动态，所以失败”，也不能量化“source uncertainty < transport uncertainty”。后者缺少同尺度且可识别的不确定性分解。每个 arm 的风变化统计来自自身轨迹，混合了位置选择和环境变化，不是独立的 House 属性。

证据包的可观测性边界：

- 有 MAP、熵、空间后验方差、更新时刻、最大概率、导航目标、传感器/风/轨迹。
- 没有完整后验网格，无法恢复真实源 rank、真源邻域质量或 carrier 质量；`candidate_count` 只是超过阈值的格点数。
- `particle_ess` 与 `covariance_trace` 为日志占位零，不可用于 ESS/输运不确定性统计。
- 没有候选源预测残差场、逐时 plume displacement 或每次 native/selected goal、trust flag，不能进行严格中介归因。
- raw sensor/wind/pose 时钟与 GSL-relative `sim_time` 起点不同。JSON 中原始流描述统计明确使用完整记录区间、包含启动/收尾；未冒充对齐后的 0–240 s 环境指标。目标重复统计基于 SENT 坐标，不等同于物理重访率。

因此本轮不能从已有包完成全部提议指标。缺失信息必须标记为缺失，不能用熵替代真源概率、用实测气体误差替代输运预测误差、用单轨迹风方差给 House 分类。

## 5. 当前结论与下一步优先级

1. M1：F00 估计与导航组合确实改变闭环；H01 seed12 有相对收益，跨 House gate 失败。不能认定思想永久无效，也不能声称正确因果源推断已被证明。
2. M2：数值场预测 PASS 保留；R4 检验的是最近风向 plume 增量，不能据它判定数值 M2 的闭环转换失败。其闭环身份对齐尚未证明。
3. M3：保留当前候选负结果；本轮没有测试它。不能把当前候选失败外推到全部 active sensing。
4. 三模块共同改善定位、或已实现 source/transport/control 不确定性分解，目前均不能作为已验证论文贡献。可以形成待验证研究问题，不能靠修改论文标题替代证明。

后续第一优先级应是只读的“场 gate 数值 M2 → 运行时接口”身份与数据可用性审计，确认输入风场条件能否在真实在线协议下成立；之后才考虑另行授权实现、冻结与实验。对于控制归因，应另行设计固定观测/固定策略对照，并补全后验及决策日志。因为 seed12 已用于事后分析，不能继续把它当新的盲测成功证据。本轮不执行这些新实验或算法变更。
