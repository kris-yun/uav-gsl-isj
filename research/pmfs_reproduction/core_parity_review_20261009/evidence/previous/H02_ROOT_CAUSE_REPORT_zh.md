# PMFS_H02_FAILURE_ROOT_CAUSE_R1

**判决：`UNRESOLVED_CONTRACT_HOLD`。** 冻结记录中的硬零排除已证实；历史运行存在多项配置偏离及不完整的物理时间／风观测血统。现有证据不能把“真源所在候选叶的 hit=0”归因到唯一工程根因，也不能升级为原生 PMFS 已合格的模型局限。到此停止旧 H02 补查。

本轮仅复用 `H02_R2026092211` 与 `H02_R2026092212`，未重建失败图谱、未启动任何新前向模拟、气体生成、ROS、Docker、训练或闭环；未修改主研究仓库，M0/M4/TNQC 的 STOP 保持原判决。

第一例存在“更新前实际 GAS HIT、累计图饱和、候选叶 hit=0”的冲突。**第二例更新前实际是 NOTHING**；相邻 raw trace 也为 0。不能将第二例写成“当时强检出但模型预测无气体”。它显示的是累计地图保留了高置信历史检出证据，而当前读数已经接近零。概率图是累积二值过滤与空间传播的结果，不是该时刻 ppm 或一组独立命中频率。第一例 logOdds 是 91.4996，75.8835 属于第二例。

官方参考代码逐次累加 logOdds 与 omega，没有在此更新路径中按时间衰减。使用 runner 的 confidenceWeight=0.5 计算 `1-exp(-omega/0.5²)`，以及 sigmoid(logOdds)，均得到双精度精确 1；随后 `1-confidence*|measured-simulated|*D` 在 D=1 时精确为 0。此链条由保存数值直接复核，不依赖任何新训练。细表与日志原句见 `SINGLE_CELL_PHYSICS_TIME_EVIDENCE.csv` 和两例 `*_last_measurement_log_excerpt.json`。

## 2. 风、帧号与采样位置：已恢复什么，缺什么

H02 日志直接确认 `useGroundTruth=false`、`Taking GMRF path`、631 个风查询位置。保存的 `estimated_wind.csv` 是该次评分使用的前向向量证据。两例全场最大风速仅 0.005634、0.005670 m/s，机器人格约 8.2×10⁻⁷ m/s；日志分别出现 3451、3453 次 “MAP did not converge after 1 iterations”。这使风观测接入／估计器求解成为优先工程线索，但不能凭报警和小风速唯一证明为何 hit=0。现场平均传感器风与平滑网格风也不能直接当成同一个随机变量。

raw wind trace 的方向与 `atan2(v,u)` 相符；参考桥接发布的是 map 坐标流向。旧 House01 源码审计中的 GMRF 来向约定存在相反方向风险。**H02 实际加载的桥接模块／GMRF 二进制哈希、接收回调和求解设置没有归档**，故本轮不宣布已经证明 H02 的 π 翻转，也不执行修复验证。

播放器的 max_iteration=1802，有 1803 个可用帧，但 replay 代码使用 `max_iteration-1=1801` 作为模数。两例全部 1500 条 raw trace 分别满足 `(344+step)%1801` 与 `(1059+step)%1801`。第二例在桥接 t=148.4 s 回绕到 frame 0；第一例在本次更新附近尚未回绕。连续 raw trace 不等于连续的原始物理羽流时间，尤其不能跨回绕称为同一连续物理实验。

数值邻近 elapsed 的 raw 帧为第一例 bridge t=189.4、frame1291，true/measured=3.374282/3.355487 ppm；第二例 bridge t=190.8、frame212，均为0。**这些仅是数值邻近记录，不能认定为 PMFS 最后消费的帧号。** exporter 参考源码的 `sim_time` 实为 `(node->now()-startTime)`，bridge 则是 `step*0.2`；两套时间原点／漂移及十条消息的 receipt 边界没有共同记录。精确有效测量时间、对应 raw 帧与 windIndex 保持缺失。生成设置中的 results_time_step=0.5 s 不能代替每帧实际时间戳。

真源叶尺寸3×1；导出的 first sampled point=(-0.4577649831771851,-1.0826042890548706)，与真源 XY 相距0.465158 m。官方代码对候选区域反复均匀采样，导出合同也只称其为 first_sampled_point。不能把此字段当作全部粒子的固定源，更不能把“含真源的叶”当作已验证的“精确真源点前向模型”。完整候选 hit-map 二进制未纳入历史包；保存的 confident-cell alignment 足以完整复算当前评分，无法补出无置信区域的完整场。

## 4. 工程问题与科学问题的边界

恢复的历史 runner／哈希绑定 launch 与官方示例在 D、风路径、预热、步长、模糊、地图过滤参数及停止判据上均有差异。官方示例 D=0.3 并不是 C1 resolved 参数，也不是所有场景唯一合法值；核心默认 D 本身为1。不能把参数差异单独称为原论文实现错误。

历史 launch 默认与 runner 显式设置 `convergence_thr=-1`。官方判据是**空间方差小于阈值**，不是“距真源足够近”。负阈值会关闭原生方差收敛声明；这与第二例方差约4.19×10⁻⁶仍继续到 timeout 一致。它解释超时标签的一个明确配置混淆，**不解释 hit=0，也不能倒推出官方配置会正确定位**。未保存的 live param dump 仍记为缺项。

最小工程处置是恢复经过 C1 实际配置解析的基线合同，核验传感器／GMRF 风向、真实高度和时间对应，启用原生合法停止判据并按精确 receipt 记录测量。短预热历史值1–3步（warmup 实际移动使用2×deltaTime，名义0.4–1.2 s）与作者示例有效200–500步有显著差别；不能在旧数据上事后调预热、风或阈值来包装改善。本轮没有应用任何代码或参数修复。

决策门：硬零 PASS；完整历史物理／时间合同 HOLD；具体工程根因 HOLD；原生 PMFS 模型失配资格 HOLD。没有完成合法原生合同的排除检查，故不能给 `QUALIFIED_MODEL_MISMATCH_SIGNAL`；工程混淆虽已定位，也未因果解释两例 hit=0，故最终不以 `CONFIGURATION_OR_RUNTIME_FAULT` 覆盖未知原因。

后续仅保留一次作者 C1 最小完整验证方案，资源与前置缺项见 `C1_MINIMAL_NATIVE_VALIDATION_PLAN_zh.md`。本轮已停止，等待下一阶段指令与该新运行的批准。
