# RK2-A 预执行只读代码审查

审查对象为工作区 `rk2_models.py`、`run_rk2.py`、`rk2_infer.py`、`test_rk2_infer.py` 和静态准备程序；本审查未运行拟合、方法预测、气体生成或新仿真。修改建议已发给主执行代理，由其统一实施，审查代理未改这些源码。

## 已发现并在工作区看到修正的缺陷

1. 缓存 frame metadata 的粒子数字段实际名是 `filament_records`；原 runner 使用 `filaments` 会在拟合前 KeyError。现已修正。
2. 原候选预测构造依赖 `divmod(reference_index, 2)` 及写死的候选 ID。原冻结顺序虽可得到正确映射，但不满足一般编号/排列透明。现已按 `candidate_hypothesis_id` 分组，并检查两个候选、每组两参考、组内物理源 XYZ 一致。候选编号不再控制物理模型分支。
3. 分位切点可能产生训练空子叶。现已在重拟合前排除，并保存 `EXCLUDED_EMPTY_TRAIN_CHILD`，不补随机切点。

## 运行前需要冻结的评价细节

审查时 `Top1_error=int(true not in top)` 会把两个候选完全并列当作无错。建议冻结：并列属于 abstain/未正确唯一定位，`Top1_error = int(len(top) != 1 or true not in top)`；另保留并列数。若采用随机打破并列的期望错误也可以，但规则必须共同、提前冻结，不能看到结果后选择较优口径。真源 NLL 不受该并列解释问题影响。

建议保留全部候选 fit logs（十个 pose 的 KKT、iteration、stop reason、耗时），而不只保存 `fit_KKT_all_pass=True`。容量输出应增加实际非零解码系数、keys/h 的数组字节以及路由编码大小。`92 bytes/state + routing` 是一个明确公共部署数组格式上限，可用于公平门；它不是 Python 字典对象的实际内存，后者需由峰值 RSS 单列。

## 未发现的信息路径错位

训练 h、S 切点和 L 分裂均仅使用四份参考，实现权重按完整 realization 等权；训练主目标只使用原 50 块访问查询。L 使用候选自己的格内 x/y、z 和 sigma 路由，不读取测试 phi/响应作路由。

runner 在打开旧留出的 compression 快照前，先冻结四臂的全部候选参考响应和纯 inference 源概率。测试隐藏状态只出现在之后明确标记的 oracle compression 表中。测试观测是实际标量浓度；候选自身物理源和所属参考分组是合法假设条件，并非真实观测生成者答案。没有 C_ORACLE 部署臂或测试真实尾项补齐路径。

infer API 只收响应预测和标量观测，严格拒绝 NPZ 的额外隐藏字段，并检查 receiver plan 一致。三项软件测试验证的是这个实际接口的隐藏文件删除、真源文件删除和编号置换透明；应按接口信息资格解释，不能提升为物理模型有效性。

## 解释边界

每个模型读出的两份候选参考同时是旧训练实现，源任务评估观测来自四份旧留出。这是合法的有限参考分类开发比较，但旧数据已经被看过，且原任务存在二源 Top1 天花板。没有增益时不应改受体、时间或温度寻找正结果。

F 的本地 Python 原生公式重新读出是真实计算成本参照，不能代表 C++ 在线延迟；源概率 scoring 的成本所有臂几乎相同，主要资源差异在候选响应构造。共同传播成本不变。数据解析耗时、模型搜索和 fallback 均需完整计入，不能只报告解码点积。

预执行结论：在以上共同并列规则及审计字段补齐后，允许执行冻结的单一 RK2-A；本结论不预判 L 的方法价值，不放行未来 B。
