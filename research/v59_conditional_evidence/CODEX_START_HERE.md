主要原生终点固定为：

\[
 e_{300}=\|\operatorname{ExpectedValue}(\texttt{sourceProbability}_{300},0.05)_{xy}-s^*_{xy}\|_2\quad\text{(m)}.
\]

调用原 C++ 函数的冻结实现；所有方法使用共同地图与物理单位。预热是否计入 300 s 沿用原生冻结基线，且各方法一致。并列报告共同 XY MAP 误差、源 rank、Brier/NLL、规定半径内概率质量、错误高置信声明、正常场景 harm、安全中断、路径/采样数、全部预测/CPU/GPU/时延/内存成本。真源及全真场仅在离线评估器中可见。

困难/正常场景按运行前的物理和可辨识条件定义，不能按 BIO 是否获胜分类。每方法所有失败/超时/安全中断均保留，统一说明不可用终点处理；不挑选最佳时刻或事后修改半径。

六个 House/seed 是**原开发 qualification**，不能叫独立 holdout，也不能将 415 重叠状态、MC样本、探头或时间窗当独立重复。以整条回合为配对单位，报告六对原始值和效应不确定性，避免小样本显著性包装。独立 test 使用尚未参与开发且事先冻结、已获授权的测试设置；当前授权不允许新造 House/seed，因此该部分可明确 OPEN，不能用六个开发回合顶替。

**H-DEV-PASS：**在六个开发回合中相对已合格同输入、同完整预算普通强对照有清晰定位净收益，且正常组损害受控；只支持开发资格。**H-DEV-FAIL：**打平/变差/成本超限应保留结果，不冻结 BIO 为主创新。**独立论文增益资格仍需独立 test 和预定消融，DEV-PASS 不是录用或生物优势保证。**

## 10. 逐阶段交付与停止规则

每阶段写独立、追加式 `stage_status.json`，包含版本、输入 hash、命令、退出码、输出 hash、PASS/FAIL/OPEN/BLOCKED、原因和下一依赖；不只写自然语言“已完成”。缺字段先导出 schema 和最小缺失清单，再继续不依赖缺字段的工作。科学资格门不自动修改论文声明、旧报告或历史运行文件。

最终交付至少包含：

1. 环境/工作树/构建/数据/模型冻结 manifest；原始文件不改。
2. 全 415 状态资格及缺失表，因果重建记录、唯一计证检查和输入 schema 验证。
3. 本轮解析程序原样结果；官方 COPEx 复现状态及其独立日志。
4. 统一全成本 ledger、cache 无效化与超预算阻断证据；不把最终 K 当全部成本。
5. 新模型的共享前向及 `C` 可达取证资格；旧 FAIL 原样保留。
6. 同状态所有方法的完整动作链、真实分支观测和失败/无差异原因。
7. 六个开发回合的 300 s 原终点、完整配对原始值、正常组 harm、端到端成本；独立 test 明确状态。
8. 一页结论按“基础正确性修复／条件理论成立／模型内动作机会／原生开发收益／独立收益”逐项裁决。某一级通过不替代下一层。

若实证显示普通完整历史/普通二阶/普通条件树已达到相同或更好结果，结论应是专门 BIO 提案未显示独立优势。保留有价值的完整方向、时间资格、联合信念和诚实计费，不通过换名或更弱对照继续包装。
