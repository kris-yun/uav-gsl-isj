# 唯一最小补充方案：未启动

本轮裁决不支持启动新模块或新闭环；以下仅定义仍需什么，**不是已执行结果，也不是自动扩大预算**。

对象只锁定2024 B4 R05的第4个源更新（580窗口原审计中的既有epoch），使用本次精确重建的历史接触状态、confidence、地图、风、实际设置。

本机旧归档中，该八回合只发现源图及接触/风状态，没有同一epoch完整最细候选前向图、owner和模拟器Gaussian/RNG快照。
2026二十配置虽然有这些字段，不能移植冒充2024 R05的历史随机状态；缺失的历史状态无法通过补一个日志文件追溯恢复。

若未来仍要核查这一特例，可做**一次只读、明确标记为新计算的原生前向诊断**：

1. 保留上述真实观测历史，使用2024原生C++前向和原配置，按原四叉树策略执行一个新epoch；不设置新的物理种子，不改轨迹、源、噪声或阈值。
2. 在新计算中被动保存所有候选图、owner、归一化前权重、源释放点、完整随机引擎、Gaussian表与索引；一次生成后O0–O3共享它们。
3. 上限建议为一个epoch、最多600个候选前向调用、180秒宿主含构建、64MiB输出。若原生自适应树超出上限，保留HOLD，不截断后冒充完整epoch；预算为提案上限，未经此轮实测吞吐保证。
4. 它能区分“2024接触表示改变是否损害固定传播下的源判别”；不能证明原R05当时的逐位因果，也不能解决PID与二维占格事件的物理同义性。

合法的仪器事件前向还缺候选各自的三维浓度响应、质量/扩散尺度、仪器高度和消费窗口积分规则。
现存二维随机释放点不能补出这些物理量；不得取真实源世界的浓度反填全部候选。
因此本轮不把该补充方案当成已经具备一个主创新，更不重建20个气体世界。
