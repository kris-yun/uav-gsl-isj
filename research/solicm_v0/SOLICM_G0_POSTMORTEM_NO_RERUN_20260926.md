# SOLICM-G0 Postmortem — No Rerun Decision

Date: 2026-09-26

Project decision:
`SOLICM_G0_NO_RERUN_IMPLEMENTATION_AND_DEPLOYMENT_CONTRACT_INVALID`

This is NOT a scientific PASS/HOLD/STOP result.
The frozen G0 gates were never evaluated because only 49/96 planned training runs completed.

## 1. Numerical execution failure

The pinned implementation fails reproducibly at:
`W2_to_W0__fold0__seed0__PL_ONLY`.

Observed diagnostics:
- model parameters remain finite;
- BatchNorm running statistics become Inf/NaN after target-domain batches;
- all four frozen checkpoints have NaN source evaluation risk;
- exact rerun repeats the failure;
- target values after source-only z-scoring reach extreme magnitudes.

Therefore the frozen implementation cannot be completed without changing the numerical/input-normalization contract.

## 2. PL_ONLY is not a functioning pseudo-label adaptation baseline

In the pinned upstream code:
- classifier already outputs a six-class Softmax probability vector;
- the pseudo-label path applies a second Softmax;
- threshold is fixed at 0.99.

For six classes, the maximum possible component after applying Softmax to a probability vector is e/(e+5) ≈ 0.3522.

Therefore the 0.99 pseudo-label threshold can never fire.
`PL_ONLY` cannot support a scientific claim about beating a functioning pseudo-label adaptation baseline.

## 3. More fundamental deployment-contract mismatch

The frozen target-unlabeled adaptation set contains 12 target-domain realizations PER SOURCE for all six candidate source classes (72 sequences per fold), with labels hidden.

This is a legitimate unsupervised-domain-adaptation benchmark construction, but it is not a legitimate deployment context for single-source gas localization.

In real deployment:
- there is one unknown true source;
- the UAV can observe gas/wind/map context generated by that unknown source;
- it does not have unlabeled target-domain plume realizations separately generated from every candidate source location.

Therefore the current G0 adaptation contract implicitly relies on a target-environment multi-source stochastic bank, even though labels are hidden.

This violates the project requirement that deployment not depend on a target-environment dense/multi-source stochastic source bank.

## 4. Consequence

Do not repair BatchNorm, change normalization, lower the pseudo-label threshold, remove the double Softmax, or rerun the 96-grid under the SOLICM-G0 charter.

Those changes would repair an implementation, but would not repair the deployment-context mismatch.

The incomplete run remains valid evidence of implementation failure only.

Do not assign a scientific SOLICM PASS/HOLD/STOP from the 49 completed runs.

JTD/NPG/RPO STOP decisions remain unchanged.

## 5. Scientific lesson to carry forward

Any future cross-environment causal/domain-adaptation mainline must state exactly what target-domain context exists when the true source is unknown.

Acceptable context may include:
- map / geometry;
- robot trajectory and timestamps;
- local wind measurements available onboard;
- observations from the same unknown leak, provided source–environment coupling is handled jointly.

Not acceptable as deployment context:
- target-domain examples separately drawn from every candidate source;
- target-domain source labels;
- target-domain dense stochastic source banks;
- full simulator wind fields unless explicitly treated as oracle/training-only information.

The next theory search should focus on task-relevant identifiability under unknown input and partial observation, not ordinary unsupervised domain adaptation.
