## 3. 对“已有大量数据，可以直接训练3D教师”的裁决

### 本轮新增的实际可训练导出

本轮已经从House02原档案合法导出 `house02_numerical_split/train.npz` 与 `dev.npz`：沿原fold0封存测试；原12训练源内固定6源训练/6源开发，各96条。原96测试响应向量没有被转换器打开。该授权依据为原 `ARCHIVE_DATA_SCOPE.json` 的offline fit许可与原source-fold预注册；不是把测试库重新命名成训练集。导出收据、原授权文件hash、每条原cube/响应hash均已保存。代码与4项实际测试在V2工程；只允许记录序号数值学习，未知物理秒和缺失局地风仍显式缺失。

S2另新增实际源盲接口回放：`s2_v2_interface/QUALIFICATION_RECEIPT.json`，DAY/NIGHT各3条当前位置真实气体/风观测、无效域区分、超20秒拒绝、零释放对照通过。它不访问private_labels、不输出整场给学生、不开展新物理模拟，也没有评价学生预测。

当前确有多源回顾性向量与真实原生3D小世界，不能把两者拼成同一数据资产。House02 的288条有多源但缺完整历史风/物理资格；S2 T0有真实可重算3D状态但只有一个源、两个短时条件。它们可以支撑不同的接口/数值开发任务。尚未找到可直接声明“合格三维、多源、多风、多实现训练世界集合”的完整本地资产。

这是有限补数的明确输入，不应导致整个系统停止。M1可先在独立标记的受控3D后端验证监督算子、数据泄漏隔离和概率自洽；之后接入通过物理资格的原生House重放/生成。每个结果必须附 backend 标签，不能把受控后端结果当House或S2收益。

## 4. 角色隔离

1. Student/runtime：几何、候选源坐标、截至当前的实际局地气体/风、位置动作时钟、仪器配置；不可访问完整风、真实源标签、实际未来响应库。
2. Teacher/train：只在训练 partition 内使用原生3D场、真实训练源标签、独立模拟器种子和传感器状态，产出源对证据/导数监督。教师不能访问冻结测试数据；教师预测不自动成为真实性真值。
3. Diagnostic：在已经开放的开发资产中用oracle风/全场解释瓶颈；明确不与合法运行基线同权限比较。
4. Evaluator：保管测试真源、完整测试世界/未来响应；只接受冻结学生/规划器动作，返回当前位置允许观测及最终指标。不能为规划器查询任意源实际响应。
