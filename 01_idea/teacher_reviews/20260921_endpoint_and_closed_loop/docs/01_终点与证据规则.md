# TNQC：终点合同与证据规则建议

日期：2026-09-21。状态：技术审查建议，非导师批准、非仓库维护者已签署的新合同。

## 核实范围

本轮 GitHub 与 raw 页面获取失败，计算环境也未能连接 GitHub。没有读取当前 V7 replay 或恢复 launch 的全文。因此，关于当前运行的事实以用户本轮提供的信息为条件，而不是声称已完成最新代码审计。已经读取前轮交付包中的报告、基准代码和结果，并重新核实 ROS 时间语义及相关研究；本轮新增了可重跑的精确数学测试。

## 1. 正式终点

建议保留冻结前规定的 native timeout -> saveResultsToFile() -> RESULT IS，以及实际链接的 ExpectedValue(sourceProbability,0.05)。日志字符串不是终点的全部定义：必须绑定 stop_reason、同一次最终 posterior/update_id、地图与网格顺序、估计函数二进制版本、时间原点与时钟。

“最后一个 sim_time <= 300 的 posterior”先只作为辅助诊断/灾难恢复值，不替换主终点。相同的估计函数不能使不同后验自动等价。只有证明两个路径取到同一 posterior/state（最好同 hash、update_id）后，才可称计算等价；否则是不同 estimand。

没有 RESULT IS 或 missing anchor 是 INVALID/INCOMPLETE（执行证据不足），不是用替代终点宣布 GO，也不是算法性能已经失败。若最终要修改正式 endpoint，应明确修订协议、说明原因、对所有比较方法统一重跑；不能只补救表现较差或缺日志的案例。先前已检查过的结果不能恢复成未见测试集。

## 2. 收尾宽限

建议允许预先固定的 wall/steady-clock I/O 宽限，但不增加科学搜索。合法条件是冻结科学状态后仅输出/复制/flush；禁止新观测进入、禁止导航或采样决策、禁止地图/后验/RNG 状态继续改变。

仅有“观测 timestamp <=300”并不充分。如果宽限时处理积压消息、继续粒子模拟、继续更新地图或完成新的推断，仍得到额外计算，至少不能称纯 flush。这可以另设固定数据预算离线评价，但不是自动等于在线 300s 预算。

必须审计 timeout 检查与 callbacks/update 的先后顺序。把 /clock 暂停在精确 300，若判断是 >300，timeout 可能永不触发；单给 wall-clock 宽限无效。可允许终止专用时钟 tick，但必须证明它不能驱动科学状态更新。需要修改状态/调度语义时，标记新版本、重新冻结并统一重跑，而不是“无影响补丁”。

离散 timer 的 nominal 300s 通常涉及 overshoot。允许的 overshoot 只能在看成绩前按机制规定并记录，不能把任意多搜索几秒改称宽限。若历史 native endpoint 已包含超过 300 的实际科学更新，必须如实报告 nominal timeout 与实测时间，不能同时声称 strict data cutoff=300。

## 3. 时钟定义

当前冻结实验的权威应是实际触发 PMFS maxSearchTime 的 clock 和 startTime；不能在看结果后换成另一个更方便的时钟。对未来统一实验，建议要求 use_sim_time=true，ROSTime 由明确且唯一的 /clock 发布者驱动，t_search = t_ROS - t0，t0 为冻结代码进入 active search 所赋的起始时刻。配置的 maxSearchTime 应给出精确值，不写约等于。

ROS 官方说明：未激活 ROS time source 时 ROSTime 与 system time 相同；激活 use_sim_time 后才由时间源驱动。因而 node->now() 这个名字本身不能证明使用模拟时间。[R1]

GADEN 原始仿真时间可能已有预热偏移、回放起点甚至循环。sensor/VGR timestamp 的含义也要单独记录。只有记录了时间域映射和漂移/偏移检验，context sim_time 才能映射到 t_search；不能只看字段名。

建议冻结句式（须先核实配置成立）：

> 本实验的搜索预算为 PMFS 搜索状态机从冻结起点 t0 起、由指定 /clock 驱动的 ROS 模拟时间 300.0 秒；权威终点为该状态机原生超时退出时保存的最终后验及 linked-native ExpectedValue(...,0.05) 输出。科学状态冻结后的固定墙钟收尾仅用于结果序列化，不接受新数据、规划或后验更新。

若原冻结 t0 或 clock 不符合这个句式，必须沿用实际定义并披露，或者做全量一致的前瞻修订。

## 4. CSV 与 .f32

按用户提供的 V7 路径，CSV 若承载所有实际读取的 candidate-support 值，可成为本次固定轨迹 replay 的完整计算输入。.f32 可以是可选 raw artifact。这里的“充分”是相对于冻结程序的计算充分，不是数学统计中的 sufficient statistic。

完整性条件：

- 所有 native final candidates × 所有有效共同 support cells 都覆盖；有明确 context_id、candidate_id、cell_id，无混用更新、重复行、隐性丢行；无只保存 top-K 或真值附近的候选。
- 保存模拟与观测概率、权重/方差或有效计数、valid mask、candidate/free-cell measure、geometry/origin/resolution、概率裁剪与 logit 规则、原生因子/先验或重建所需全部参数。具体哪些字段需要由冻结消费者的依赖决定。
- 浮点精度足以复现：float32 通常需要 9 位有效十进制数字，float64 需要 17 位才能保证一般值往返；必须用实际文件的误差检查而非只看列数。候选排序、并列处理也要一致。
- 源真值仅供 evaluator；建立无 TNQC native reconstruction -> linked-native anchor 的数值一致性检查。

不能仅因扩展名是 .csv 就认可，也不能仅因缺 .f32 就否决。当前 CSV 未提供，因此本轮不能确认这些条件已满足。

更重要：当前 fixed-trajectory CSV 充分，不代表对新动作的闭环评估充分。它没有实际机器人未走位置的真实未来观测；.f32 模拟模板也不是那些位置的实测。下一代动作规划至少还需要 action-conditioned 预测、传感器时序模型与独立的离线环境/高保真回放来检验反事实。

## 5. 恢复 launch 的 provenance

持久盘恢复文件可以作为后续重复运行的 recovered configuration，但不能证明它与旧实验逐字节一致。只有“唯一找到”的事实也不能证明唯一存在或历史同一性。

立即保存：恢复源路径、恢复时间、当前 SHA-256、所有 include/参数文件/环境变量/命令行展开值、resolved parameters、namespace/remap/QoS、binary SHA、Git commit与dirty patch、编译配置、依赖、地图/风场/场景哈希、种子、clock 设置。文件名日期、mtime、复制成功均不能替代旧 hash。

建议用恢复后同一配置重跑 baseline 与新方法，形成新的、当前可追溯的配对比较。旧论文成绩只能保留为 provenance-limited historical reference，不与新试验混作同一批。是否认可为原冻结合同的正式 launch，需要项目负责人作有记录的决策；本审查没有老师的原始 hash。

## 6—8. 研究原则决议

6：当前 TNQC 应收紧为特定 hit-logit 表征中的正仿射 observation/calibration nuisance canonicalization；transport-aware source templates 与 transport invariance 是不同声明。

7：建议下一代选 B 作为问题对象，A 仅用于确有群结构的 calibration 子问题，并将唯一主创新候选推进到“动作如何主动破除源—输运混淆”。不建议仅因一次 V5 HOLD 就无原则换方向，也不建议给一般风场强行命名 nuisance orbit。

8：目前“物理约束 quotient + 检查 identifiability”的一句话仍不够强。应形成物理可辨识条件、可执行的短时主动探测规划、相对强基线的有限预算收益证据。Fisher/Schur、BOED、dual control、世界模型这些已有概念本身不是新贡献。
