# Failure-informed research doctrine before the next main-innovation cycle

Date: 2026-09-23
Branch: `research/cross-domain-mother-idea-audits-20260923`

Status: **PREPARATION ONLY — NO NEW METHOD IS NAMED OR PROMOTED**

## 0. Purpose

This document is intentionally written before the next cross-domain mother idea is converted into a gas-source-localization method.

The goal is to prevent recurrence of the two main failure modes already observed:

1. **discovery-set success without intervention generalization**;
2. **endpoint improvement without true source identity**.

No idea receives a method name, V1 label, frozen formula, or holdout until it passes the necessary-mechanism screens below.

---

# 1. Failure ledger

## 1.1 HCMC / cross-scale structure-function conformance

What looked strong:
- old six discovery: about 56% endpoint reduction, 6/6;
- strong scale-family robustness;
- strong spatial / spectral destructive controls.

What failed:
- true independent plume validation produced a scientific NO-GO;
- one valid independent plume made the frozen representation undefined:
  - 0 valid HCMC candidates;
  - 0 valid slope comparisons;
  - zero posterior mass;
- five evaluable independent cases gave only about 14.3% improvement, 2/5 non-worse, and one false-confident collapse.

Lesson:
- a statistic can be strongly structured and still be **realization-specific**;
- mathematical definability under low-information / constant-field states must be tested before promotion;
- cross-realization invariance cannot be inferred from old-seed stability.

## 1.2 HCCE / causal-emergence transfer

What looked strong:
- old + independent plume development pool: about 54.8%, 12/12;
- leaf permutation 0/1000;
- temporal shift / block destruction / candidate mismatch all strongly separated;
- high same-house cross-realization score correlation.

What failed:
- candidate-level truth identity was weak despite endpoint improvement;
- cross-transport source-identity kill test on controlled CStar:
  - HCCE-style causal-emergence identity: 2/12;
  - trivial encounter-rate matching: 10/12.

Lesson:
- strong temporal structure can encode **transport regime / encounter organization**, not source identity;
- source identity under intervention must be tested before endpoint localization is trusted;
- top-5% centroid can hide poor candidate truth rank.

## 1.3 HCTLA / transition-law alignment

What looked interesting:
- old discovery approximately 41.7%, 5/6;
- useful destructive controls.

Why it cannot currently be treated as validated:
- new accepted independent-plume package contains only one source update per run;
- the method requires multiple update transitions;
- missing updates cannot be reconstructed.

Lesson:
- never call a method validated when the required state sequence is absent;
- classify such ideas as **DATA-INELIGIBLE**, not positive or negative.

## 1.4 HCDG / diffusion geometry

What looked positive:
- roughly 25–33% discovery gain, often 6/6.

Why it was demoted:
- destructive-null separation was too weak;
- too many random leaf permutations matched or exceeded the real score.

Lesson:
- aggregate improvement alone is insufficient if score-to-location coupling is weak.

## 1.5 ACIA / invariant-causal and IDG transfers

What looked positive:
- ACIA proxy roughly 33.6%, 5/6;
- IDG proxy approximately 10%.

Why they were rejected:
- weak environment-permutation / null separation;
- inconsistent cross-seed source-score reproducibility;
- insufficient intervention evidence.

Lesson:
- "OOD" or "causal" language does not substitute for a concrete source-specific mechanism.

## 1.6 Partial identification

What was scientifically sound:
- explicit broad identified sets under model misspecification;
- avoids false confidence.

Why it is not the main localizer:
- source sets became too broad for useful localization.

Lesson:
- retain as a possible **abstention/safety layer**, not force it into the main inference mechanism.

## 1.7 Mori–Zwanzig direct proxy

What looked superficially positive:
- delayed candidate forcing improved endpoint metrics.

What failed:
- delayed forcing did not give the truth-nearest candidate source-specific held-out predictive benefit;
- residual-memory score failed destructive controls;
- current PMFS bank only supplies a time-averaged candidate field, not true candidate-conditioned dynamics.

Lesson:
- "using history" is not equivalent to observing an MZ memory kernel;
- do not infer a high-level physical mechanism from features that the data representation has already temporally averaged away.

# 2. The five questions every new mother idea must answer before any method is built

## Q1. Which observed failure does the mother idea explain?

Allowed targets:
- stochastic-realization shift;
- transport intervention shift;
- source-position intervention;
- low-information / degeneracy states;
- geometry shortcut;
- temporal averaging / hidden dynamics;
- endpoint-vs-source-identity mismatch.

If the idea only supplies a new descriptor without addressing one of these, discard it at literature stage.

## Q2. What observation would have to exist if the mother idea were true?

Write a falsifiable necessary condition before a localization score.

Examples:
- response theory: fixed source under transport perturbation must follow a reproducible response law;
- transfer operator: probability / material transport evolution must preserve source-specific operator action across realizations;
- LCS: source mass should be constrained by a stable transport skeleton under the relevant wind field;
- large deviations: source-conditioned path-action should separate same-source from wrong-source trajectories;
- intervention equivariance: source-conditioned observations should transform under the intervention according to a reusable map.

If no such minimal phenomenon can be stated, do not build a localization algorithm.

## Q3. Does the required information exist physically and causally?

Classify every required variable as:

- `ALREADY_EXPORTED`
- `COMPUTED_BUT_DISCARDED`
- `AVAILABLE_IN_RAW_DATASET`
- `REGENERATABLE_WITH_EXISTING_SIMULATOR`
- `TRULY_UNAVAILABLE`
- `NON_CAUSAL_NOT_ALLOWED`

A missing CSV column is not evidence that the physical information is unavailable.

## Q4. Can the mechanism survive source × transport intervention?

Before endpoint optimization, the idea must answer:
- same source, changed transport: does source identity survive by invariance, equivariance, or a predictable response?
- different source, same transport: does the signal actually change?

The CStar SA/SB × fast/slow asset should be used as an early binary mechanism screen whenever the needed observables exist.

## Q5. Does the effect survive anti-shortcut metrics?

Mandatory diagnostics:
- direct candidate truth rank;
- nearest-truth candidate percentile;
- top-candidate source distance;
- full-posterior expected distance;
- mass within 1 m / 2 m;
- MAP error;
- geometry-only baselines;
- very simple physical/statistical baselines.

Top-5% ExpectedValue is never sufficient by itself.

# 3. Promotion ladder for future main innovations

No new idea may skip a stage.

### Stage A — literature / mother-theory validity
- genuinely external to GSL/OSL;
- strong 2025–2026 anchor preferred;
- public code strongly preferred;
- exact GSL collision screen.

### Stage B — data eligibility
- required observables audited;
- causal online availability separated from simulation-only ground truth;
- no missing-state fabrication.

### Stage C — necessary mechanism
- no localization posterior yet;
- test the one phenomenon that must exist if the mother theory transfers.

Fail => immediate NO-GO.

### Stage D — development localization
Only after Stage C passes:
- old six;
- unblinded independent-plume six;
- no truth-tuned hyperparameters.

### Stage E — intervention identity
- source × transport;
- source-position transfer when available;
- shortcut controls.

### Stage F — anti-metric gaming
- candidate-level truth identity;
- full posterior;
- MAP;
- radius mass;
- simple baselines.

### Stage G — method naming and freeze
Only here:
- give the method a name;
- freeze formula;
- freeze hyperparameters;
- write code and protocol;
- generate a never-inspected holdout.

### Stage H — fresh holdout
Must change at least:
- stochastic realization;
- source position;
and ideally transport regime.

Only after PASS:
- closed-loop planning;
- auxiliary innovations.

# 4. Data-acquisition doctrine

The algorithm is allowed to change **what it records or how long it observes** when the underlying dataset/simulator actually provides that information and the acquisition is causal.

Examples that are allowed in principle:
- retain 3 s of wind history instead of 1 s;
- export PMFS candidate internal simulation dynamics that are already computed and then averaged away;
- store per-measurement values inside a StopAndMeasure block;
- reconstruct past spatial wind fields from recorded data if the raw field genuinely exists;
- generate source-blind stochastic replicas from the existing forward simulator.

Not allowed:
- future wind;
- future gas;
- future robot trajectory;
- true source position as an input;
- simulator-only ground truth that a real online system could never estimate, unless the paper explicitly treats it as an oracle ablation rather than the deployed algorithm.

The central distinction is:

> **"PMFS does not currently export it" is not equivalent to "the problem does not contain it."**

# 5. Candidate mother-idea map — no promotion yet

These are only categories for future audit.

## A. Nonequilibrium fluctuation–response theory

2025–2026 external science:
- response of nonlinear nonequilibrium systems to perturbations;
- response kernels / fluctuation–response relations.

Why it addresses a known failure:
- HCCE showed that transport changes destroy naive "same signature" assumptions.
- Response theory instead predicts **how the same source should change** under a transport perturbation.

Required information:
- time-resolved perturbation (wind / transport);
- time-resolved response;
- same-source paired interventions;
- preferably spatial wind history.

First kill test:
- without source localization, test whether a source-fixed fast→slow response mapping is more reproducible within source than across source.

## B. Perron–Frobenius / transfer-operator transport

2025–2026 external science:
- evolution of densities / mass under nonlinear dynamics;
- coherent sets / mixing compartments.

Why it addresses a known failure:
- focuses on **transport action on mass**, not static plume appearance.

Required information:
- time-resolved candidate material / occupancy evolution;
- flow field or transition dynamics;
- source injection.

First kill test:
- does the estimated transport operator map source-conditioned mass forward consistently across stochastic realizations and distinguish SA from SB under matched geometry?

## C. Lagrangian coherent structures / FTLE

External science:
- transport barriers, attracting/repelling manifolds and coherent transport corridors.

Why it addresses a known failure:
- source plume realizations may differ while still being constrained by the same finite-time transport skeleton.

Required information:
- time-resolved spatial velocity field, not only robot-local wind.

First kill test:
- can source identity be recovered better from relation to the transport skeleton than from trivial encounter rate under fast/slow intervention?

## D. Large deviations / trajectory ensembles

External science:
- path-space probability, rare trajectories, dynamical partition functions.

Why it addresses a known failure:
- plume intermittency is path-level stochastic behavior; averaging can destroy source information.

Required information:
- multiple stochastic trajectories per source or a source-conditioned stochastic forward generator;
- complete encounter trajectories.

First kill test:
- same-source trajectory action / path statistic must cluster across independent stochastic realizations and remain distinct across sources.

## E. Intervention equivariance / symmetry discovery

External science:
- physical systems need not be invariant under intervention; they may transform equivariantly.

Why it addresses a known failure:
- fast→slow plume should not be expected to remain unchanged.

Required information:
- paired interventions;
- known intervention variable;
- enough repeated source-fixed pairs to infer a transformation.

First kill test:
- learn/estimate a transport transformation without source truth, then test whether it maps same-source fast↔slow better than wrong-source pairs.

# 6. Current priority before Codex finishes the information inventory

Do not select one mother idea yet.

Wait for the audit to resolve:

1. actual runtime `iterationsToRecord` and `deltaTime` in accepted runs;
2. whether PMFS candidate dynamics can be exported per internal timestep;
3. whether candidate simulation uses one frozen wind grid or can causally consume a wind-history sequence;
4. whether GADEN `wind_iteration_0..10` contains complete spatial fields;
5. whether full historical estimated-wind grids can be recovered;
6. storage / parity cost of dynamic candidate export.

The answer to those questions determines which of A–E can be tested honestly.

# 7. Research behavior rule

Before naming any future method, write a one-page audit with exactly four headings:

1. **Mother theory**
2. **Necessary phenomenon**
3. **Available observation**
4. **Kill test**

Only if the kill test is passed may a fifth heading appear:

5. **Possible source-localization construction**

This is now the default research discipline for the project.
