# GADEN–PMFS dynamic-information inventory (2026-09-23)

Scope: read-only audit of commit `c5271515d565c343d2fd2a63c77bf0484f45772a` and the six frozen HCMC-independent accepted runs. No HCMC or other method is tested here. Classification describes the **accepted-run artifacts**, not every optional logger in the repository. `ONLINE` means available at or before the current decision time without simulator truth; `ORACLE` means simulator-only and forbidden as an online algorithm input. Counts/sizes below are estimates, not new observations.

## Correction to the handoff premise

`SimulationSettings` initializes `iterationsToRecord=100`, `deltaTime=0.1` (`internal/Settings.hpp:39-40`), but `PMFSLib::GetSimulationSettings` replaces those with ROS defaults 200 and 0.2 (`PMFSLib.cpp:453-459`). The accepted-run launcher explicitly passed `iterationsToRecord:=200`, `deltaTime:=0.2`, `minWarmupIterations:=1`, `maxWarmupIterations:=3` (`reference/run_hcmc_v1_independent_gate_20260922.sh:254-259`). Thus each accepted candidate records **200 steps / nominal 40 s of internal model time**, after warmup; it is not a 100-step / 10 s run. This model time is not synchronized to the 300 s robot trajectory or GADEN playback clock.

Six runs each contain only `source_update_0001`: H01 A/B 152/152 candidates; H02 A/B 180/164; H03 A/B 193/193 (1034 total). Each has 1500 rows in sensor, pose and local-wind traces; all source-update times are ~189.5–217.7 s. Existing `candidate_maps/` are empty although manifest `hit_map_file` fields name `.f32` files. The current usable candidate map export is only the observed-support slice in `candidate_support_alignment.csv`, not a full dynamic tensor or even a full saved map.
