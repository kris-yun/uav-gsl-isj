## Frozen question

Does the official cross-physics GeoPT pretrained representation provide a
low-data gas-forward advantage over the *same architecture with random frozen
weights*?

This is the most direct causal test of the M6 main claim.

## Design

- official `GeoPT_8layers.pt`, SHA256 verified;
- all 3,862,848 non-head pretrained parameters loaded;
- identical 8-layer Transolver architecture in both arms;
- identical 16,961-param source adapter;
- identical 257-param gas head;
- backbone frozen in both arms;
- 25% source-blind geometry-hash label subset: 141 / 651 free tokens;
- training combinations:
  - S1-W1;
  - S2-W1;
  - S1-W2;
- fully held-out development recombination:
  - S2-W2;
- training target averages both plume realizations and all ten saved times;
- evaluation keeps plume A/B separate;
- training seeds: 1729, 2718;
- fixed 80 epochs, AdamW, lr=1e-3, weight decay=1e-5.

No S2-W2 target entered training or model selection.

## Actual checkpoint/runtime prerequisite

G0.5-B passed before this experiment:
- official artifact hash exact;
- internal non-head tensor coverage: 100%;
- released input contract verified as `pos3 + fx11 -> 14`;
- real House02 forward succeeded.

Therefore this G1 failure is not explained by missing checkpoint weights or an
input-width mismatch.

Aggregate:

- mean pretrained/random MSE ratio: **1.66492**;
- mean source-margin change (pretrained - random): **-0.06920**.

Both arms rank the true source first among only two candidates in all four
comparisons. This is an uninformative floor and does not rescue M6.

Training loss is also consistently worse for the pretrained-frozen arm:
- seed1729 final: 0.17812 pretrained vs 0.07739 random;
- seed2718 final: 0.19279 pretrained vs 0.07526 random.

## Interpretation

The official GeoPT representation is technically compatible and cheap, but its
cross-physics features do **not** transfer positively to this scarce-data
House02 gas-forward task under the frozen source-adapter contract.

The negative result is large, consistent across both optimization seeds and
both independent plume realizations, and directly targets the claimed value of
pretraining.

Possible scientific reasons include:
- pretraining-task/domain bias;
- obstacle-constrained random-walk features not aligning with turbulent scalar
  concentration;
- fixed pretrained representation being too task-specific for gas transport.

Those are explanations, not grounds to rescue the same claim.

## Frozen stop

Do not:
- unfreeze GeoPT layers after this negative frozen-transfer result;
- alter prompt scaling against S2-W2;
- increase adapter capacity;
- search source-injection position using the opened holdout;
- generate the planned 12-source GADEN bank for M6;
- integrate M6 into ROS/PMFS closed loop.

A larger fine-tuned GeoPT might fit gas data, but that would no longer test the
main M6 claim that cross-physics pretraining gives a low-data advantage.

## Status

**M6 closed as main innovation.**

The real-world deployment charter remains useful as a generic standard for any
future mainline, but no M6 flight work is justified.
