# Lagoon 定位数据合同恢复

本轮目标是恢复源定位输入合同。没有执行新 GADEN、闭环或观测规划，也没有用七个通量采样点去调参。

## 已经解决的部分

此前 flight 与 flight_frec 的对应关系未核实。现在从数据内容独立重建，而非按行号配对：

- 13 个合并航段的 U、V、W 和 Time 与原始 Trisonica 文件逐值一致，包括缺失掩码；每个航段只有一个匹配。
- GPS 的纬度、经度、相对高度和 yaw 四字段联合匹配，154389 条有效记录全部匹配到唯一原始飞行。
- 甲烷、湿度、气体仪器纬度和经度四字段联合匹配，15364 条记录全部匹配到唯一原始采集批次。
- 以 GPS 实际 datetime 而非规则 tfs 计算 UTM 东向、北向前向差分速度。对所有 169 个 flight / flight_frec 组合核对。13 个正确组合的最大绝对误差为 9.751e-8 m/s，每个次优组合 RMSE 大于 0.1 m/s。

因此得到 flight 0..12 对应 flight_frec 0..12。这个结果虽然数值上与 ordinal pairing 相同，但证明来自独立的数值重算。全部比较结果已保存。

原始 GPS 飞行行号依次为 1,4,5,6,7,11,12,13,14,22,23,24,25；Aeris 采集批次行号为 0,1,1,1,1,2,2,2,2,4,4,4,4，全部使用零基索引。

## 尚不能声称解决的部分

作者在 Zenodo 指定的 https://github.com/johanage/lagoon-pingo-analysis.git 当前返回 404。账号公开仓库查询正常返回 200，共 14 个仓库，其中没有该项目。不能把这个 404 归为令牌不足或整个 GitHub 不可达。

正确的飞行映射不等于完整物理合同。ucorr/vcorr/wcorr 的实际坐标方向、安装变换、平滑与平台运动修正尚未唯一重建。尝试了不同轴置换、符号、欧拉旋转顺序、仪器与飞控姿态、平台报告速度与 GPS 差分速度、多个平滑窗口，没有得到机器精度复现。因此不能把最接近的公式当作作者公式。

官方 LI-560 手册明确 PI 是 pitch，RO 是 roll，P 是压力；数据字段 R0 是否来自 RO 的重命名仍需处理代码确认。仪器允许配置单位与轴方向，默认值不能证明本次安装配置。

官方手册：https://www.licor.cn/uploads/20240110/560-TriSonica-Sphere_Manual_20375.pdf.pdf

同一规则网格上的合并记录和原始文件身份已经核实，但各仪器时钟调整方法、气体传感器物理响应滞后尚未获得可复现说明。不能用甲烷与风的相关性去拟合一个方便定位的滞后。

GPS 差分速度存在远高于飞控报告速度的尖峰。它可以证明维度映射，但不能直接作为可信的无人机运动补偿量。

## 对源定位的具体意义

现在可以确定每个航段的气体、GPS、原始风和发布修正风属于哪一次飞行。已导出源定位候选输入 CSV，保留最近 GPS/风记录的网格时间偏差，不进行隐式插值和滞后修正。CSV 每行明确标注 physical_wind_and_lag_verified=False；该文件不是已通过物理合同的正式定位基准。

当前不能给出可辩护的唯一精确泄漏源坐标，也不能把七个 Excel 通量/逸散记录直接当作单一点源真值。计算一个位置后验与用独立真值评价定位误差是两项不同要求。

下一项定位前置工作应只针对剩余合同：恢复作者真实风修正及传感器时钟/响应说明，再冻结源位置未知的反演模型。若官方代码仍未公开，需要的最小材料是生成 ucorr/vcorr/wcorr 的函数及配置、各仪器时间变换、气体响应延迟说明。没有对外发送联系消息。

本轮判定：RECORD_LINEAGE_UNLOCKED_PHYSICAL_WIND_AND_LAG_UNRESOLVED。旧 HOLD 证据包保留，本轮只更新已经被新证据解决的条款。
